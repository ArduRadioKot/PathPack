# PathPack v0.7: проверка иерархии поверх расписания v0.4

Дата: 2 ноября 2026. v0.4, v0.5, v0.5.1 и v0.6 не менялись. Их прогоны `output/v04_dev`, `output/v05_dev`, `output/v051_dev`, `output/v06_dev` и `output/v04_graph_probe` не перезаписывались. Новый код — метод `pathpack-v7`. Счётчик токенов прежний: `utf8_bytes_div4_ceil_serialized_context_v1`, ceil(число байт UTF-8 / 4) всего сериализованного контекста. Это не токенизатор Gemma.

Конфигурация `configs/pathpack_v07.yaml` записана до прогона и после чисел не менялась. Проверка с потолком замены вынесена в отдельный файл `configs/pathpack_v07_capped.yaml` и отдельный каталог `output/v07_cap_dev`. Holdout не запускался.

## Почему v0.4 обгоняет v0.6

Числа v0.6 взяты из уже посчитанного `output/v06_dev` при 2048 токенах. File Recall считается на 20 задачах, Function и Complete на 18, Changed Line на 14. У 4 задач метки полные, у 16 частичные. Чистая вставка не входит в Changed Line Recall и не считается нулём.

| Метод | File | Function | Complete | Changed line | Latency, с |
| --- | ---: | ---: | ---: | ---: | ---: |
| pathpack-v4 | 0.725 | 0.202 | 0.091 | 0.148 | 0.615 |
| pathpack-v6 | 0.600 | 0.226 | 0.060 | 0.172 | 2.504 |

File Recall. У v0.4 первый слот бюджета многих файлов занимает короткий чанк: так в контекст входит больше файлов. У v0.6 этого бонуса нет, а prior родительской функции снижает File Recall (без него 0.700, у полного v0.6 0.600). При 2048 v0.6 теряет золотые файлы `psf__requests-1766`, `scikit-learn__scikit-learn-13439`, `sphinx-doc__sphinx-11510` и половину файлов `astropy__astropy-8707`.

Complete Function Recall. Срез редко покрывает 100% тела функции: 0.060 против 0.091. Целые функции (`no-chunking`) поднимают Complete до 0.226 и роняют File Recall до 0.500, потому что одна функция съедает бюджет. Эти две цели конкурируют за одни и те же токены.

Changed Line Recall. Лучший локальный срез v0.6 помог только `astropy__astropy-8707` (0 → 0.333). Парный интервал включает 0. Глубина графа 3 не добавила покрытых строк относительно глубины 1: на всех 14 оцениваемых задачах строки совпали.

Latency. Второй проход BM25 по целым функциям даёт 2.504 с против 0.615 с у v0.4.

## Гипотеза v0.7

Расписание файлов остаётся решением v0.4: один индекс BM25, разнообразие, граф глубины 2. Внутри файла первый фрагмент заменяется представлением лучшей функции этого файла. Короткая функция, если все её срезы укладываются в 192 токена, берётся целиком. Иначе берётся срез с наибольшим `lexical / sqrt(tokens + 32)`. Повторные интервалы строк не пакуются второй раз. Порядок не зависит от бюджета, поэтому контекст 1024 является префиксом 2048 и 4096.

Глубина графа не увеличивалась. Проба hops=3 на v0.4 уже показала, что лишний переход не даёт подтверждённого прироста строк.

```
order ← PathPack v0.4(query)          # hops = 2, diversity включено
for chunk in order:
    if файл chunk ещё не открыт:
        f ← функция файла с наибольшим lexical
        if adaptive и все срезы f укладываются в 192 токена:
            unit ← целая f
        else:
            unit ← срез f с max lexical / sqrt(tokens + 32)
        if cap_to_opening и unit дороже открывающего чанка v0.4:
            unit ← открывающий чанк
        выдать unit и не выдавать открывающий чанк повторно
    else:
        выдать chunk, если его интервалы ещё не заняты
упаковать префиксы под 1024, 2048, 4096
```

В зафиксированном конфиге `cap_to_opening` выключен. Это поле появилось только в повторной проверке.

Аудит бюджета, уникальности интервалов и вложенности префиксов прошёл. BM25, Graph Expansion, v0.5.1 и v0.6 в этот прогон не пересчитывались; их числа ниже взяты из `output/v06_dev` на тех же задачах и том же счётчике. ## Где v0.7 проиграл и где выиграл

При 2048 отличия от v0.4 есть только на четырёх задачах.

- `sphinx-doc__sphinx-11510`: File 1 → 0. Это единственная потеря файла. В v0.4 контекст содержит 12 файлов и 18 чанков (2033 токена), открывающие чанки стоят 1359 токенов. В v0.7 остаётся 10 файлов и 14 чанков (2029 токенов), открывающие единицы стоят 1621 токен. Выпали `sphinx/builders/epub3.py` и `sphinx/directives/other.py`. Замена часто указывает на другую функцию и стоит больше короткого чанка v0.4: например, первый чанк `conf.py` в 67 токенов заменён срезом `linkify_issues_in_changelog` в 213 токенов.
- `astropy__astropy-8707`: Function и Complete 0.5 → 0, Changed Line 0 → 0.333. Та же единственная задача, на которой v0.6 поднимал строки.
- `sphinx-doc__sphinx-7985`: Function 0 → 1, строки остаются 0.
- `sympy__sympy-13878`: Function 0.143 → 0.071, Complete 0.143 → 0.071, Changed Line 0.071 → 0. Частичное попадание v0.4 потеряно.

## Абляции при 2048

Каждая строка — те же 20 задач и тот же бюджет. `no-hierarchy` совпадает с v0.4 по всем четырём метрикам на каждой задаче. Значит, при выключенной замене код возвращает порядок v0.4.

| Вариант | File | Function | Complete | Changed line | Что изменилось |
| --- | ---: | ---: | ---: | ---: | --- |
| v0.7 | 0.675 | 0.226 | 0.060 | 0.167 | зафиксированная гипотеза |
| no-hierarchy | 0.725 | 0.202 | 0.091 | 0.148 | порядок v0.4 без замены |
| no-adaptive | 0.675 | 0.226 | 0.060 | 0.167 | целые функции не меняют ни одну метрику |
| no-graph | 0.675 | 0.167 | 0.056 | 0.167 | граф v0.4 держит функции, не строки |
| no-budget | 0.675 | 0.282 | 0.060 | 0.310 | срез по lexical, без деления на sqrt(tokens) |
| no-diversity | 0.475 | 0.135 | 0.079 | 0.167 | без разнообразия v0.4 файлов меньше |

Слияние функции короче 192 токенов не отличимо от «всегда срез»: `no-adaptive` совпадает с полным v0.7 на всех задачах и всех трёх бюджетах. Адаптивная гранулярность в этой форме не сработала.

Отключение нормировки на стоимость (`no-budget`) оставляет File 0.675 и Complete 0.060. Function 0.282 и Changed Line 0.310 выше по точке. Парная разность `no-budget` минус v0.4: File −0.050, ДИ [−0.150, 0.000], 0/19/1; Function +0.079, ДИ [−0.060, 0.270], 2/14/2; Complete −0.032, ДИ [−0.087, 0.000], 0/16/2; Changed Line +0.162, ДИ [0.000, 0.357], 3/10/1. Интервал строк включает 0. Выигрыши строк: `astropy__astropy-8707` 0 → 0.333, `sphinx-doc__sphinx-7985` 0 → 1, `sympy__sympy-24213` 0 → 1. Проигрыш строки: `sympy__sympy-13878` 0.071 → 0. Файл `sphinx-doc__sphinx-11510` по-прежнему потерян. Этот вариант не зафиксирован как новый конфиг: он был абляцией, а не заранее выбранной гипотезой, и File с Complete остаются хуже v0.4.

Разнообразие v0.4 нужно для файлов. Без него File Recall 0.475. При 1024 разность против v0.4 равна −0.200, ДИ [−0.375, −0.050], ноль в интервал не входит. Граф, выключенный вместе с заменой, не поднимает строки при 2048. При 4096 точка File у `no-graph` равна 0.850, разность против v0.4 +0.050, ДИ [0.000, 0.150], одна задача, интервал включает 0.

## Повторная проверка: замена не дороже открывающего чанка

Потеря файла объясняется ростом открывающих единиц. Вторая проверка разрешает замену только если она не дороже открывающего чанка v0.4. Остальные коэффициенты те же. Это `configs/pathpack_v07_capped.yaml`, прогон `output/v07_cap_dev`, 120 предсказаний, аудит прошёл.

На всех 20 задачах и всех трёх бюджетах четыре метрики совпали с v0.4: разность 0, ДИ [0, 0], 0 побед и 0 поражений. Контексты при этом не все совпали: 38 из 60 пар одинаковы, 22 различаются, и на каждой задаче при 2048 в контекст входит хотя бы одна замена. Замены, которые помещаются в слот короткого чанка, не двигают золотые файлы, функции и строки.

Дальше перебор коэффициентов не делался. Замены, которые поднимают строки в `no-budget`, крупнее открывающего чанка. Потолок, который сохраняет файл, эти замены отсекает. Свободных токенов почти нет: utilization v0.4 при 2048 равен 0.992. Добавить срез, не вытеснив хвост расписания, некуда, а порядок обязан оставаться одним и тем же для всех бюджетов.

## Что здесь не является новой моделью

BM25, типизированный обход графа, жадная префиксная упаковка и выбор чанка по убыванию оценки — стандартные части v0.4. v0.7 их не заменяет. Иерархия в этом прогоне — одно правило: первый фрагмент файла может быть другим представлением той же функции или другой функции того же файла. Это не многоступенчатый поиск с отдельным индексом файлов, как в v0.5, и не второй BM25, как в v0.6.

Проверяемая гипотеза для статьи: расписание файлов и локальное представление можно выбирать независимо, не теряя файлы, которые купило разнообразие v0.4. На этих 20 задачах гипотеза не подтвердилась. Более полезный срез стоит больше короткого открывающего чанка и выталкивает следующий файл. Потолок стоимости возвращает метрики к v0.4. Отдельной статьи по этому отрицательному результату здесь нет: дедлайн 12 ноября 2026, а критерий успеха на независимых данных не выполнен.

## Воспроизведение

Нужны уже собранные `output/benchmark/issues.jsonl` и `data/swebench/snapshots`. Оценка читает кэш `output/benchmark/hf_cache` в режиме `HF_HUB_OFFLINE=1`.

```bash
.venv/bin/python -m unittest discover -s tests -q
.venv/bin/python -m codegraph_rag benchmark \
  --issues output/benchmark/issues.jsonl \
  --snapshots data/swebench/snapshots \
  --out output/v07_dev --split dev \
  --method pathpack-v4 pathpack-v7 \
  --budgets 1024 2048 4096 \
  --config configs/pathpack_v4.json \
  --v7-config configs/pathpack_v07.yaml \
  --v7-ablations
.venv/bin/python -m codegraph_rag score-run --run output/v07_dev
.venv/bin/python -m codegraph_rag audit --run output/v07_dev
```

Повтор команды в существующий каталог с `run.json` отказывается перезаписывать прогон. Повторная проверка потолка:

```bash
.venv/bin/python -m codegraph_rag benchmark \
  --issues output/benchmark/issues.jsonl \
  --snapshots data/swebench/snapshots \
  --out output/v07_cap_dev --split dev \
  --method pathpack-v4 pathpack-v7 \
  --budgets 1024 2048 4096 \
  --config configs/pathpack_v4.json \
  --v7-config configs/pathpack_v07_capped.yaml
.venv/bin/python -m codegraph_rag score-run --run output/v07_cap_dev
```

Блокнот `notebooks/08_pathpack_v07.ipynb` показывает замену на учебном репозитории и читает эти два прогона. Holdout `output/v05_holdout` не оценивался: v0.7 не превзошёл v0.4 по четырём метрикам, а снимки 60 задач этого списка не выкачаны.
