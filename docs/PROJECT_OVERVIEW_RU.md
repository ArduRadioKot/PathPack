**Исследовательская записка · 1–2 ноября 2026 · версия 0.2**

## 1. Концепция

**Задача:** помогать небольшим локальным ИИ-моделям находить нужный код в больших Python-репозиториях, не передавая им весь проект.

**Проблема:** семантический поиск может находить фрагменты, близкие по смыслу к описанию ошибки, но пропускать функции и файлы, от которых зависит исправление. При небольшом контекстном окне нельзя просто добавить весь репозиторий.

**Наша гипотеза (ещё не проверена):** выбор связанного подграфа с учётом описания ошибки и бюджета токенов даст более высокую полноту локализации ошибки, чем BM25, поиск по эмбеддингам и простое расширение графа.

**Рабочая новизна:** PathPack, алгоритм выбора полезных *путей зависимостей* и упаковки фрагментов в фиксированный бюджет токенов. Графовый поиск кода существует; нельзя выдавать сам факт использования графа за новизну. Новизну предстоит доказать сравнением с опубликованными методами.

## 2. Как работает система

1. **Вход:** описание GitHub Issue и Python-репозиторий на коммите *до исправления*.
2. **AST-парсер:** получает определения модулей, классов, функций и методов.
3. **Граф:** формирует направленные связи `defines`, `imports`, `calls`, `inherits` (только статически разрешённые).
4. **Поиск точек входа:** BM25/эмбеддинги находят несколько релевантных функций.
5. **PathPack (следующий этап):** выбирает пути по графу, штрафует избыточность и стоимость в токенах.
6. **Выход:** ограниченный, объяснимый контекст для локальной LLM.
7. **Оценка:** ищем изменённые в эталонном исправлении файлы и сравниваем методы при равном бюджете.

Функция полезности для будущего PathPack как **рабочая идея**, а не проверенная реализация:

`Q(S) = α·Relevance(S) + β·Connectivity(S) − γ·Redundancy(S)`

при ограничении `Tokens(S) <= B`, где `B ∈ {1024, 2048, 4096}`.

## 3. Что уже реализовано

- Статический сканер Python через `ast`, без выполнения кода проекта.
- Узлы: модуль, класс, функция, метод; у каждого путь и номера строк.
- Рёбра: определения, импорты, разрешённые вызовы, наследование.
- Экспорт графа в JSON, запуск через CLI.
- Подготовка формата задач SWE-bench Verified со строгим разделением текста задачи и эталонных меток.
- Визуализация графа в PNG/SVG, интерактивное исследование в Jupyter Notebook (при запуске ячеек).

**Пока не сделано:** алгоритм PathPack; BM25 и embedding retrieval; скачивание реального SWE-bench Verified в этом комплекте; эксперимент на реальных задачах; реальное исправление ошибок Gemma 4. Графы из примера и исходников проекта иллюстративные, не являются оценкой качества исправления багов.

## 4. Что показывает граф

- `defines`: модуль определяет функцию/класс; класс определяет метод.
- `imports`: модуль импортирует другой модуль или символ.
- `calls`: функция вызывает другую, если цель удалось разрешить статически.
- `inherits`: класс наследуется от локально разрешённого базового класса.

**Ограничения:** динамическая диспетчеризация, monkey patching, `getattr`, сложные алиасы и внешние библиотеки могут не иметь ребра. Отсутствие ребра **не означает** отсутствия зависимости.

См. `visualizations/sample_graph.png` (малый пример) и `visualizations/parser_calls.png` (вызовы вокруг собственного AST-парсера).

## 5. Экспериментальный протокол

- Источник: SWE-bench Verified; сначала 80 задач, 20 dev и 60 test.
- Вход ранжировщику: только `problem_statement`, исходники на `base_commit` и граф, извлечённый из них.
- Метки из `patch` хранятся отдельно, **никогда не участвуют в поиске**.
- Baselines: BM25; embeddings; BM25 + graph neighbors; PathPack.
- Метрики: file recall@budget, MRR (если определено на уровне ранжирования), время поиска, количество токенов; patch success rate только после интеграции агента и проверки тестами.
- Для честности одинаковый бюджет токенов, разбиение на чанки и тестовый набор.
- Статистика по ошибкам парсера и неполным связям должна публиковаться.

## 7. Как запустить

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[viz]'
python -m unittest discover -s tests -v
codegraph scan examples --out output/example-graph.json
codegraph visualize output/example-graph.json --out visualizations/my_graph.png
jupyter notebook notebooks/01_code_graph_research.ipynb
```

Для реальных метаданных потребуется интернет и дополнительный пакет:

```bash
pip install -e '.[benchmark,viz]'
codegraph prepare --out output/benchmark --limit 80 --dev-count 20 --seed 42
```

`codegraph prepare` не скачивает исходники репозиториев и не запускает тесты SWE-bench.
