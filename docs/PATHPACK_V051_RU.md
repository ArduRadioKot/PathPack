# PathPack v0.5.1: один цикл после отрицательного результата v0.5

Дата: 2 ноября 2026. Пакет 0.5.1. v0.4 и v0.5 не переписывались. Новая конфигурация `configs/pathpack_v051.yaml` проверяет три изменения сразу, без перебора коэффициентов:

1. **Soft hierarchy.** FileScore остаётся признаком чанка. Жёсткий потолок 24 файла и порог 12% больше не выкидывают файл из пула (`enable_file_filter: false`).
2. **Dual granularity.** Релевантность файла считается по целым функциям, в контекст попадают мелкие чанки. Крупный фрагмент сам в контекст не копируется.
3. **Бонус первого чанка равен нулю.** Штраф повторного чанка того же файла остаётся и обнуляется только при ChunkScore = 1 (`local_resistance: 1`).

Четыре клетки эксперимента — это `pathpack-v51` и три варианта. Все они делят нулевой бонус и soft hierarchy, кроме `global-fine`, где FileScore выключен и внутрифайловая перенормировка тоже.

| Метод | Поиск файлов | Контекст |
| --- | --- | --- |
| `pathpack-v51` | целые функции | мелкие чанки |
| `pathpack-v51/coarse-coarse` | целые функции | целые функции |
| `pathpack-v51/fine-fine` | мелкие чанки | мелкие чанки |
| `pathpack-v51/global-fine` | без FileScore, глобальный порядок | мелкие чанки |

Прогон: 20 dev-задач, бюджеты 1024/2048/4096, счётчик `utf8_bytes_div4_ceil_serialized_context_v1`. Аудит бюджета и вложенности префиксов прошёл. Holdout не запускался: этот цикл не дал основания фиксировать метод. Embedding baseline по-прежнему не выполнен.

Цель цикла — поднять Changed Line Recall относительно v0.4 и не потерять его File Recall — не выполнена для основного `pathpack-v51`. Прирост строк равен одной задаче, `astropy__astropy-8707` (0 → 0.333), и интервал касается нуля. File Recall при этом 0.625 против 0.725.

`global-fine` — единственная клетка с File Recall не ниже v0.4 (0.775) и с тем же единичным приростом строк. Function Recall у неё 0.143 против 0.202 у v0.4. Интервалы включают ноль. Этого недостаточно, чтобы заменить v0.4 или открывать holdout.

## Что разделил эксперимент

Мелкий контекст лучше крупного. `coarse-coarse` даёт File Recall 0.325 и Changed Line Recall 0.071. Разница File Recall между мелким контекстом и целыми функциями на этих 20 задачах имеет интервал [0.05, 0.55]. Крупный фрагмент полезен как гипотеза для оценки файла, но как содержимое контекста он занимает бюджет и промахивается по строкам.

Оценка файла по целым функциям не вернула File Recall v0.4. `pathpack-v51` и `fine-fine` оба имеют File Recall 0.625. Разница строк между ними снова равна той же одной задаче astropy.

Глобальный порядок мелких чанков без FileScore набирает больше эталонных файлов, чем dual-granularity. На строках они совпали на всех 14 оцениваемых задачах. FileScore целой функции в этой реализации не является тем сигналом, который дотягивает изменённую строку.

Пример из v0.5, `sklearn` `_get_blas_info` (ChunkScore 0.803, позиция 24, штраф файла 0.179), в v0.5.1 имеет нулевой штраф и нулевой бонус, но стоит на позиции 62 и в бюджет 2048 не входит. Впереди оказались другие чанки с более высокой полезностью на токен, в том числе короткие фрагменты `setup.py` и примеров. Снятие бонуса убрало правило «один чанк с файла», но не сделало этот срез первым.

Запрос v0.5.1 занимает около 0.90 с против 0.57 с у v0.4. Индекс целых функций в latency запроса не входит.

## Changed Line Recall v0.4 по задачам

Среднее 0.1480 одинаково при 1024, 2048 и 4096, потому что оно одинаково на каждой задаче. Из 14 задач с оцениваемыми старыми строками ни одна не получила новую покрытую строку при росте бюджета. 6 задач имеют null на всех трёх бюджетах: для них нет непустой удалённой или заменённой строки в `base_commit`. File Recall при этом вырос от 1024 к 4096 на 6 из 20 задач. Дополнительные токены добавляют файлы и не добавляют изменённые строки. Это не артефакт усреднения и не смещение номеров: строки, которые уже покрыты при 1024, остаются покрытыми, а непокрытые остаются непокрытыми.

## Категории F и E

По диагностике v0.4 @2048 у эталонных функций, для которых кандидат попал в лог, нет случая «ребра нет». 14 функций имеют положительный GraphScore. 21 функция имеет ребро и GraphScore 0: путь от зёрен BM25 до неё не дошёл. Категория F (16 задач) в аудите означает нулевой графовый счёт у лучшего эталонного кандидата, а не отсутствующее ребро. Часть таких функций всё равно выбрана лексически, например `ClearableFileInput.use_required_attribute`.

Категория E совпадает с ограничениями разметки, а не с ошибкой графа. Полная разметка есть у 4 из 20 задач. Исключения: 23 вставки без старой строки, 14 новых определений, которых нет в `base_commit`, 13 неразрешённых границ вставки, 5 изменений вне функции. Changed Line Recall эти случаи не обнуляет: они остаются вне знаменателя.

## Что не делается в этом цикле

Счётчик `ceil(UTF-8 bytes / 4)` не заменён токенизатором Gemma. Замена сделала бы несопоставимыми v0.4, v0.5 и v0.5.1. Её место — отдельный пересчёт перед статьёй, одним и тем же токенизатором для всех методов. Embedding `all-MiniLM-L6-v2` не запускался: `sentence-transformers` не установлен.

Holdout `output/v05_holdout/` остаётся нетронутым. Основной версией для статьи по измеренным метрикам остаётся v0.4. Вопрос «может ли поиск на нескольких уровнях детализации улучшить локализацию строк, не теряя файлы» на этом цикле получил ответ: мелкий контекст лучше крупного, а оценка файла по целым функциям файлы не сохранила.
