# PathPack v0.8: срезы только в промежутке между файлами v0.4

Дата: 2 ноября 2026. v0.4, v0.5, v0.5.1, v0.6 и v0.7 не менялись. Их прогоны не перезаписывались. Счётчик токенов прежний: `utf8_bytes_div4_ceil_serialized_context_v1`. Конфиг `configs/pathpack_v08.yaml` записан до прогона и после чисел не менялся. Holdout не запускался.

## Что взято из предыдущих версий

v0.4 по-прежнему лучше всех по файлам: короткий первый чанк и разнообразие приводят золотые файлы. v0.5 отсекал файлы потолком. v0.6 и v0.7 ставили более точный срез на место этого чанка и выталкивали следующий файл. Глубина графа 3 на v0.4 поднимала строки только на `psf__requests-1766`, интервал включал 0. Второй проход BM25 в v0.6 занимал 2.5 с и снижал File Recall.

Отсюда правило v0.8. Порядок и сами открывающие чанки остаются решением v0.4: один BM25, разнообразие, граф глубины 2. Токены, которые v0.4 тратит после открывающего чанка и до следующего нового файла, можно потратить заново. В этот промежуток входит срез уже открытого файла с наибольшим lexical. Целая функция берётся только если она помещается и в промежуток, и в 192 токена. Срез не может стоить больше промежутка, поэтому следующий файл не сдвигается за границу бюджета. Порядок один на все бюджеты, 1024 остаётся префиксом 2048 и 4096.

```
order ← PathPack v0.4(query)          # hops = 2, diversity включено
opened ← пусто
for chunk in order:
    if файл chunk ещё не открыт:
        выдать chunk как якорь
        opened ← opened ∪ {файл}
        gap ← сумма токенов хвоста до следующего нового файла
        выдать лучшие срезы файлов из opened, пока они укладываются в gap
    хвост v0.4 в этом промежутке больше не выдаётся
упаковать префиксы под 1024, 2048, 4096
```

Проверка на сохранённом порядке v0.4, ещё до кода v0.8, показала границу метода. Если отдать все хвостовые токены новым файлам, File Recall при 2048 не растёт: ни один дополнительный золотой файл в эти токены не попадает. Пропущенные строки при этом часто лежат в срезе, который короче самого длинного промежутка между файлами. v0.8 проверяет именно эту перестановку, а не новый ранжир файлов.

При 2048 отличаются две задачи.

- `astropy__astropy-8707`: Changed Line 0 → 0.333. Та же задача, на которой строки поднимали v0.6 и v0.7.
- `scikit-learn__scikit-learn-13124`: Function 1 → 0. У v0.4 покрытие `StratifiedKFold._make_test_folds` равно 0.286, у v0.8 остаётся 0.086. Второй чанк той же функции был в хвосте и оказался заменён срезом с более высоким lexical. Порог функции — 20% тела, поэтому функция выпала.

Latency 0.951 с выше 0.592 с у v0.4: на каждый промежуток заново просматриваются срезы уже открытых файлов. Это один ранг v0.4, без второго BM25.

По бюджетам у полного v0.8 строки плоские: 0.172 при 1024, 2048 и 4096. File при 1024 равен 0.575 против 0.525 у v0.4, разность +0.050, ДИ [0.000, 0.150], одна задача. Function при 1024 и 2048 ниже на ту же задачу sklearn.

## Абляции при 2048

`no-deepen` совпадает с v0.4 по всем четырём метрикам на каждой задаче. Замена хвоста — единственное отличие полного v0.8.

| --- | ---: | ---: | ---: | ---: |
| v0.8 | 0.725 | 0.147 | 0.091 | 0.172 |
| no-deepen | 0.725 | 0.202 | 0.091 | 0.148 |
| no-adaptive | 0.725 | 0.147 | 0.091 | 0.172 |
| no-graph | 0.675 | 0.115 | 0.060 | 0.172 |
| no-diversity | 0.475 | 0.147 | 0.091 | 0.187 |

Слияние функций короче 192 токенов снова ничего не меняет: `no-adaptive` совпадает с полным v0.8 на всех задачах и бюджетах. Без графа v0.4 файлов и функций меньше. Без разнообразия File Recall падает до 0.475.

Отдельно, не как новый конфиг: при 4096 у `no-diversity` Changed Line равен 0.330 против 0.148, разность +0.182, ДИ [0.024, 0.372], 4/10/0. Ноль в этот интервал не входит. File при этом 0.775 против 0.800, потеря — половина файлов `mwaskom__seaborn-3187`. При 2048 тот же вариант имеет File 0.475. Разнообразие выключать нельзя: выигрыш строк на большом бюджете сопровождается потерей файла. `configs/pathpack_v08.yaml` из-за этого наблюдения не менялся.

## Почему комбинация не обходит v0.4

Промежуток между файлами — единственные токены, которые можно перераспределить, не выталкивая следующий файл. Эти токены у v0.4 уже заняты хвостом. Хвост иногда добирает функцию до порога 20%, как в sklearn. Срез с более высоким lexical иногда попадает в изменённые строки, как в astropy. Одни и те же токены не могут сохранить оба исхода. Оставить хвост на месте означает вернуть v0.4. Заменить его означает обмен одной функции на строки одной задачи, без подтверждённого интервала.

Нового ранжира файлов v0.8 не вводит. Предыдущие ранжиры, которые меняли набор файлов, теряли File Recall. Упаковка якорей v0.4 при 2048 уже включает все золотые файлы, до которых дотягивается этот порядок.

## Воспроизведение

```bash
.venv/bin/python -m unittest discover -s tests -q
.venv/bin/python -m codegraph_rag benchmark \
  --issues output/benchmark/issues.jsonl \
  --snapshots data/swebench/snapshots \
  --out output/v08_dev --split dev \
  --method pathpack-v4 pathpack-v8 \
  --budgets 1024 2048 4096 \
  --config configs/pathpack_v4.json \
  --v8-config configs/pathpack_v08.yaml \
  --v8-ablations
.venv/bin/python -m codegraph_rag score-run --run output/v08_dev
.venv/bin/python -m codegraph_rag audit --run output/v08_dev
```

Повтор в каталог с готовым `run.json` отказывается перезаписывать прогон. Блокнот `notebooks/08_pathpack_v08.ipynb` читает этот прогон. Holdout `output/v05_holdout` не оценивался.
