# CodeGraph-RAG / PathPack v0.3: статус и результаты

> Исторический отчёт из исходного архива v0.3. После объединения локальные
> snapshots и сырые predictions прежнего прогона доступны в общем проекте.
> Актуальная точка входа — `notebooks/03_swebench_pathpack.ipynb`;
> подробности сохранения данных и различий метрик — `docs/MERGE_V03_RU.md`.

Дата: 1 ноября 2026. Основа: исходники v0.2 и агрегированные результаты, присланные пользователем на скриншоте.

## Что добавлено

1. `pathpack-v3`: новая экспериментальная стратегия выбора функций. Совмещает BM25, совпадение имён файлов и функций с запросом, графовую близость, бонус разнообразия файлов. Порядок фиксируется независимо от бюджета, а упаковка берёт только префикс ранжирования. Это гарантирует, что набор при 1024 является подмножеством набора при 2048 и 4096 для одного и того же проекта и запроса. Недостаток: может оставлять бюджет неиспользованным.
2. `codegraph audit`: проверка выходных JSONL на превышение бюджета, несоответствие учёта токенов, повторение узлов и нарушение вложенности, сопоставление попаданий по файлам и функциям, парный bootstrap с фиксированным seed. Требует сырые предсказания по задачам и отдельный gold-файл.
3. `codegraph gold-functions`: **только после retrieval** вычисляет приблизительные метки функций, изменённых в патчах, по AST исходного снимка и изменённым строкам. Добавления и изменения вне функций размечаются неполно. Эталонный патч не используется для поиска.
4. Обновлённый scorer поддерживает необязательное поле `gold_functions` в gold JSONL. Если оно отсутствует, function recall не вычисляется.
5. Дополнительные тесты и воспроизводимый искусственный microbenchmark.

## Реальные результаты, присланные пользователем (НЕ повторно измерены этой версией)

На test (60 задач), согласно скриншоту:

| Budget | BM25 File Recall | Graph Expand | PathPack v0.2 | BM25 Function Recall | PathPack Function Recall |
|---:|---:|---:|---:|---:|---:|
| 1024 | 0.4639 | 0.3847 | 0.4417 | 0.1749 | 0.1821 |
| 2048 | 0.5181 | 0.4444 | 0.5806 | 0.2583 | 0.2348 |
| 4096 | 0.5514 | 0.4986 | 0.6236 | 0.2949 | 0.2535 |

При бюджете 4096 PathPack обгоняет BM25 по File Recall на 0.0722, но отстаёт по Function Recall на 0.0414. На dev File Recall у BM25 снижается с 0.65 до 0.625 при росте 2048→4096, а у PathPack с 0.60 до 0.575. При одинаковом полном наборе задач и вложенном selection такого быть не должно. Возможные причины: пересортировка/замена фрагментов, метрика, пропущенные результаты, изменившаяся выборка. **Агрегированной таблицы недостаточно для диагностики причины**.

Внимание: сырые JSONL результатов SWE-bench не входили в переданный архив, поэтому текущая версия не была запущена на этих 80 задачах. Графики ниже визуализируют именно агрегаты скриншота, не новые измерения.

## Честный microbenchmark v0.3 (4 искусственные задачи, budget 110)

- BM25: 0/4 file hits.
- Graph Expansion: 4/4.
- PathPack v0.2: 4/4.
- PathPack v0.3: **3/4**.

v0.3 **ещё не улучшает точность**. Её проверенное преимущество на данном этапе: детерминированный вложенный отбор контекста на тестируемых бюджетах. Устаревший toy-набор нельзя использовать как доказательство на SWE-bench.

## Следующий воспроизводимый эксперимент

1. Установить пакет (`pip install -e .`). Запустить на **dev** все 4 метода и три бюджета, см. `scripts/run_dev.sh`.
2. Запустить `codegraph audit` на полученных JSONL и `gold_labels.jsonl`. Для анализа `function_recall` нужна отдельная разметка `gold_functions`; команда `gold-functions` строит её из патчей на этапе scoring. Запросам/retriever патчи недоступны.
3. Посмотреть `diagnostic_cases` в `audit_dev.json`, особенно случаи "верный файл, неверная функция". Улучшать ранжирование только на dev.
4. После фиксации параметров использовать **новую, ещё не просмотренную test-выборку**. Уже исследованные 60 задач нельзя корректно назвать полностью нетронутым holdout после выбора изменений под результаты. Нужна новая зафиксированная выборка из оставшихся задач, по возможности без пересечения репозиториев.

## Ограничения

- Бюджет по-прежнему приблизительный (`ceil(UTF-8 bytes/4)`), не токенизатор Gemma.
- Разметка изменённых функций = proxy, а не гарантия причины ошибки.
- Диапазон латентностей нельзя сравнивать с другими машинами без одинаковых условий и кэширования.
- Нет результатов patch success / обучения Gemma и нет полного dense embedding baseline.
- Только 22 теста и учебный протокол в текущем окружении, не оценка исследовательской новизны.
