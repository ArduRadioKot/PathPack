# Оптимизация PathPack: диагноз, v0.5.1 и проверка графа

Дата: 2 ноября 2026. Выборка: 20 dev-задач SWE-bench Verified, seed 42, манифест `output/benchmark/issues.jsonl`. Счётчик токенов везде один: `utf8_bytes_div4_ceil_serialized_context_v1`, то есть `ceil(число байт UTF-8 / 4)` всего сериализованного контекста, включая пути и заголовки. Это не токенизатор Gemma. Эталонный патч читается только после упаковки контекста.

Основной baseline остаётся **PathPack v0.4** (`configs/pathpack_v4.json`, `hops: 2`). v0.5 и v0.5.1 на этой выборке его не заменяют. Конфигурации `configs/pathpack_v05.yaml` и `configs/pathpack_v051.yaml` после своих прогонов не подбирались. Каталоги `output/v04_dev`, `output/v05_dev` и `output/v051_dev` не перезаписывались.

Полная разметка есть у 4 из 20 задач. Function Recall считается на 18 задачах, Changed Line Recall на 14. Чистая вставка не входит в Changed Line Recall: для неё нет непустой удалённой или заменённой строки. Bootstrap: 2000 итераций, seed 42, парная разность по `instance_id`, 95% интервал. Интервал, который включает 0, не считается подтверждением.

## Подтверждённые причины

Цифры ниже взяты из `output/v05_dev`, `output/v051_dev`, `output/v05_audit` и повторного чтения предсказаний v0.4. Это не предположения о том, «как должен работать» ранжировщик.

| Вопрос | Что проверено | Подтверждённая причина |
| --- | --- | --- |
| A. Почему v0.5 теряет файлы | Порог 12% от лучшего файла и потолок `max_files=24`. На 19 из 20 задач пул равен 24. Семь эталонных файлов отсечены причиной `file_cap` на рангах 25–563. Ещё два попали в пул, но первый чанк начинается около 2116–2120 токенов и виден только при бюджете 4096. | Жёсткий Top-24 после порога выбрасывает эталонные файлы до упаковки. Средний FileScore пропущенных эталонных файлов 0.52, у неэталонных файлов внутри контекста 0.68. Символьный вклад около 0.03. |
| B. Почему найденный файл не даёт строки | В предсказаниях v0.4 @2048 у 8 эталонных файлов, которые уже лежат в контексте, покрыты не все изменённые строки. Полностью покрыт один такой файл. Пять эталонных файлов в контекст не попали. Пример sklearn: файл `_split.py` выбран, функция `_make_test_folds` — нет; все её чанки упираются в лимит на файл. | Первый выбранный срез файла — не изменённые строки. Бюджет внутри файла уходит в другой фрагмент. |
| C. Почему строки v0.4 не растут от 1024 к 4096 | По каждой из 14 оцениваемых задач Changed Line Recall одинаков на трёх бюджетах: 14 без изменения, 0 с ростом, 0 с падением. Шесть задач имеют null на всех бюджетах, потому что в патче нет непустой старой строки. File Recall при этом растёт на 6 из 20 задач. | Дополнительные токены добавляют другие файлы. Нужный срез уже выбранного файла в префикс не входит. Это не ошибка сопоставления номеров строк. |
| D. Почему граф иногда вредит | У записанных эталонных функций v0.4 нет случая «ребра нет». 14 функций имеют GraphScore > 0, 21 имеет ребро и GraphScore 0: путь от трёх зёрен BM25 не дошёл. Аудит F (16 задач) означает нулевой графовый счёт лучшего эталонного кандидата, а не дыру в графе. Отключение графа у v0.4 снижает File Recall 0.725 → 0.675 и поднимает Changed Line Recall 0.148 → 0.172. | Обход двунаправленный и ограничен двумя переходами. Он доносит релевантность не до всех связанных эталонных функций и одновременно двигает порядок чанков. Категория F может стоять и на задаче, которая выбрана лексически. |
| E. Почему diversity держит File Recall | У v0.4 отключение diversity роняет File Recall с 0.725 до 0.425. У v0.5 отключение diversity оставляет File Recall 0.575 и поднимает Function Recall до 0.163 и Changed Line Recall до 0.172, а плотность падает до 0.041. Порядок детерминированный: бонус первого чанка файла и штраф похожести, не случайная раздача бюджета. | Diversity в v0.4 покупает файлы ценой первого чанка многих файлов. Поэтому рост бюджета не покрывает изменённые строки. |

Доля токенов v0.4 @2048 в путях `examples/`, `docs/`, `setup.py` и `conf.py` равна 0.144. В эталонных файлах лежит 0.072, в остальной библиотеке 0.784. Примеры занимают заметную, но не главную долю. Основной расход — библиотечный код, который не содержит изменённых строк.

Офлайн-обход сохранённых графов v0.4 от трёх лексических зёрен: из 35 эталонных функций 3 сами являются зёрнами, 12 достижимы за 1 переход, ещё 2 за 2, ещё 9 только за 3, 9 недостижимы и за 3. Глубина 2 структурно не доходит до 9 функций. Это ещё не значит, что глубина 3 улучшит упакованный контекст: см. пробу ниже.

## PathPack v0.5.1

Реализация остаётся в `pathpack-v51`. При выключенных новых флагах `V5Config` повторяет v0.5. В `configs/pathpack_v051.yaml` FileScore не фильтрует файлы (`enable_file_filter: false`), файл оценивается по целым функциям, бонус первого чанка равен 0, `local_resistance` равен 1, `candidate_limit` равен 512. Коэффициенты 0.20 / 0.50 / 0.18 / 0.12 не менялись.

Формула `α·Chunk + β·File + γ·Graph + δ·DiversityGain` как новая линейная сумма не вводилась. DiversityGain по-прежнему бонус и штраф поверх формулы, а не четвёртое слагаемое. Отдельный перебор δ на тех же 20 задачах не делался.

Пять клеток детализации соответствуют четырём измеренным вариантам. «Soft Hierarchy → Chunk» совпадает с `fine-fine`: файл не отсекается, FileScore считается по чанкам, в контекст идут чанки. Отдельного пятого прогона нет.

| Клетка | Метод | File | Function | Complete | Changed line | Density (n) | Latency, с |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| baseline | pathpack-v4 | 0.725 | 0.2024 | 0.0913 | 0.1480 | 0.0403 (9) | 0.568 |
| Function → Chunk | pathpack-v51 | 0.625 | 0.1984 | 0.0873 | 0.1718 | 0.1425 (10) | 0.901 |
| Function → Function | coarse-coarse | 0.325 | 0.0833 | 0.0833 | 0.0714 | 0.2000 (5) | 0.600 |
| Chunk → Chunk и Soft Hierarchy → Chunk | fine-fine | 0.625 | 0.1429 | 0.0873 | 0.1480 | 0.1472 (9) | 0.780 |
| Global → Chunk | global-fine | 0.775 | 0.1429 | 0.0873 | 0.1718 | 0.1276 (11) | 0.816 |

Бюджет 2048. Latency v0.4 в этой колонке — повторный прогон `output/v051_dev`. В `output/v05_dev` тот же контекст v0.4 даёт 0.607 с. Метрики v0.4 совпали.

Парная разность, кандидат минус v0.4:

| Кандидат | Метрика | Разница | 95% ДИ | + / = / − |
| --- | --- | ---: | --- | --- |
| v0.5.1 | File | −0.100 | [−0.30, 0.10] | 1 / 16 / 3 |
| v0.5.1 | Function | −0.004 | [−0.167, 0.163] | 1 / 15 / 2 |
| v0.5.1 | Changed line | +0.024 | [0.00, 0.071] | 1 / 13 / 0 |
| global-fine | File | +0.050 | [−0.10, 0.20] | 2 / 17 / 1 |
| global-fine | Changed line | +0.024 | [0.00, 0.071] | 1 / 13 / 0 |

Единственный прирост строк у v0.5.1 и у global-fine — `astropy__astropy-8707`, с 0 до 0.333. File Recall v0.5.1 ниже v0.4. global-fine выше по файлам на точечной оценке и ниже по функциям (0.143 против 0.202). Ни один интервал не исключает ноль в пользу замены v0.4.

Плотность на пересечении задач, где она определена у обоих методов: v0.4 и v0.5.1, n=9, 0.0403 против 0.1583; v0.4 и global-fine, n=9, 0.0403 против 0.1560. Более высокая плотность v0.5.1 не компенсирует потерю файлов и не выходит за пределы тех же задач, где у v0.4 плотность уже определена. Сравнивать опубликованные средние с разным n (8, 9, 10, 11) нельзя.

На тех же 20 задачах при 2048 токенах, прогон `output/v05_dev`: BM25 File 0.350 / Function 0.111 / Changed line 0.143, latency 0.053 с; Graph Expansion 0.325 / 0.111 / 0.143, latency 0.153 с; v0.5 0.575 / 0.115 / 0.148, latency 0.496 с. v0.5 совпадает с собой при 1024 и 2048 на всех 20 задачах: добавленные 1031 токен в среднем — это 156 чанков новых файлов и 2 чанка уже выбранных файлов, без нового эталонного файла.

## Граф: глубина и направление

Текущая формула v0.4 не заменялась суммой `Σ SeedScore(s) · edge_confidence(path) · decay^distance`. Сравнивался тот же обход: вес ребра умножается на 0.8 на каждом шаге, зёрна своего графового бонуса не получают. Проба `output/v04_graph_probe` один раз сканирует репозиторий и пять раз вызывает этот ранжировщик. Бюджет только 2048. Время сканирования и индекса в latency не входит: среднее сканирование 5.93 с, индекс 3.21 с. Упаковка префикса занимает около 0.0002 с. Почти вся latency запроса — это ранжирование, 0.58–0.67 с.

| Вариант | File | Function | Complete | Changed line | Density (n) |
| --- | ---: | ---: | ---: | ---: | ---: |
| hops 1, оба направления | 0.700 | 0.1468 | 0.0913 | 0.1480 | 0.0454 (8) |
| hops 2, оба направления (v0.4) | 0.725 | 0.2024 | 0.0913 | 0.1480 | 0.0403 (9) |
| hops 3, оба направления | 0.725 | 0.2619 | 0.0952 | 0.2194 | 0.0445 (9) |
| только вызывающие, hops 2 | 0.600 | 0.1151 | 0.0595 | 0.1480 | 0.0470 (8) |
| только вызываемые, hops 2 | 0.750 | 0.1468 | 0.0913 | 0.1718 | 0.0456 (9) |

File Recall hops 3 совпал с hops 2 на всех 20 задачах. Рост Function Recall — две задачи: `psf__requests-1766` (0 → 1) и `sympy__sympy-13878` (0.143 → 0.214). Рост Changed Line Recall — только `requests-1766` (0 → 1). Парный интервал hops 3 минус hops 2 для строк: +0.071, 95% ДИ [0.00, 0.214], 1 победа, 13 ничьих, 0 поражений. Для функций: +0.060, [0.00, 0.171], 2 / 16 / 0. Оба интервала включают 0.

Только вызывающие функции хуже по файлам (−0.125, ДИ [−0.275, 0.00], 0 / 17 / 3). Только вызываемые дают File Recall 0.750 за счёт одной задачи и теряют функцию на одной задаче. Двунаправленный обход не стоит заменять одним направлением по этим 20 задачам.

Конфиг `configs/pathpack_v4_hops3.json` сохранён, чтобы пробу можно было повторить. Он не заменяет `configs/pathpack_v4.json`. Среднее 0.219 по строкам не объявляется улучшением: его создаёт одна задача, а интервал включает ноль.

## Гипотезы

Подтвердились.

- Жёсткий потолок файлов v0.5 выбрасывает эталонные файлы до упаковки.
- Changed Line Recall v0.4 плоский на каждой задаче, а не только в среднем.
- Целые функции как содержимое контекста хуже мелких чанков: File Recall coarse-coarse 0.325 против 0.625 у v0.5.1, интервал разницы файлов [0.05, 0.55] не включает 0.
- Diversity v0.4 — детерминированный механизм «первый чанк многих файлов», а не случайное перемешивание.
- Категория F — недошедший путь от зёрен, а не отсутствующее ребро. Категория E — ограничения разметки.

Не подтвердились.

- Soft hierarchy и оценка файла по целым функциям сохраняют File Recall v0.4 и поднимают Changed Line Recall. File Recall упал до 0.625. Прирост строк — одна задача, интервал включает 0.
- Нулевой бонус первого чанка продвигает сильный срез внутри файла. У sklearn `_get_blas_info` позиция изменилась с 24 на 62.
- Глубина 3 или одно направление рёбер дают устойчивый выигрыш по строкам. Выигрыш глубины 3 сосредоточен в одной задаче.
- Линейный член δ·DiversityGain. Он не вводился: предыдущие изменения diversity уже измерялись абляцией, а новый коэффициент на тех же 20 задачах был бы подгонкой.

Ориентиры 0.75 / 0.25 / 0.15 / 0.20 при 2048 токенах не достигнуты методом, который можно поставить вместо v0.4. Точечные 0.262 и 0.219 у hops 3 не проходят парный интервал и не трогают Complete Function Recall заметным образом (0.091 → 0.095, одна задача).

## Что не проверялось

- Holdout `output/v05_holdout` (60 идентификаторов, seed 44, пересечение с dev и прежними списками пустое). Снимки этих репозиториев не развёрнуты, и ни одна конфигурация не обошла v0.4 с интервалом, исключающим 0. Прогон не запускался и после него коэффициенты не подбирались.
- Embedding `sentence-transformers/all-MiniLM-L6-v2` ревизии `c9745ed1d9f207416be6d2e6f8de32d1f16199bf`. Пакет не установлен, статус `not_run`. Другой метод под этим именем не подставлялся.
- Токенизатор Gemma. Смена счётчика сделала бы несопоставимыми уже посчитанные методы. Её место — полный пересчёт всех методов одним счётчиком.
- Сумма графового счёта по всем зёрнам вместо текущего лучшего пути. Сравнивались глубина и направление текущего пути.
