# PathPack v1.0: Evidence Graph Optimization не заменяет v0.4

Дата: 3 ноября 2026. v0.4 остаётся основным методом. Совместный отбор по свидетельствам из текста задачи не обошёл v0.4 ни по одной из четырёх метрик на диагностических 20 задачах при бюджете 2048. Это отрицательный результат, а не повод менять коэффициенты задним числом.

Прогоны v0.4–v0.9 не перезаписывались. Счётчик токенов прежний: `utf8_bytes_div4_ceil_serialized_context_v1`, `ceil(UTF-8 bytes / 4)` по всему сериализованному контексту. Конфиг `configs/pathpack_v10.yaml` записан до измерения и после чисел не менялся. Git-коммита в рабочей копии нет (`git rev-parse HEAD` пустой). Seed bootstrap 42, 2000 итераций, парная разница по задачам.

Эти 20 задач уже много раз использовались для выбора архитектуры. Они годятся для диагноза и не являются независимым подтверждением. Отдельные validation и final holdout не оценивались: локально лежат только 80 снимков исходных dev/test, а списки `output/v04_holdout` и `output/v05_holdout` не имеют снимков. Манифест записан до прогона: `output/v10_splits/manifest.json`.

## Решение

Заменять v0.4 на v1.0 не следует.

При 2048 токенах, один и тот же прогон `output/v10_diag`:

| Метод | File | Function | Complete | Changed line | Загрузка бюджета | Latency, с |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| pathpack-v4 | 0.725 | 0.2024 | 0.0913 | 0.1480 | 0.992 | 0.583 |
| pathpack-v10 (joint) | 0.475 | 0.1706 | 0.0595 | 0.0765 | 0.348 | 0.329 |
| coverage, без графа | 0.425 | 0.0556 | 0.0556 | 0.0714 | 0.120 | 0.329 |
| dependency paths | 0.375 | 0.1944 | 0.0833 | 0.1667 | 0.501 | 0.328 |
| nested joint | 0.500 | 0.2024 | 0.0913 | 0.1820 | 0.399 | 0.344 |
| joint без structural | 0.425 | 0.0556 | 0.0556 | 0.0714 | 0.120 | 0.331 |
| joint без semantic | 0.475 | 0.1706 | 0.0595 | 0.0765 | 0.348 | 0.337 |

File Recall считается по 20 задачам, Function и Complete по 18, Changed Line по 14 задачам с непустыми удалёнными или заменёнными строками. Чистые вставки в Changed Line не входят. У 16 из 20 задач метки неполные; задачи без значения метрики в среднее не подставляются нулём. Аудит бюджетов, повторных интервалов и зависимостей прошёл. `fallback_used` равен 0 на всех 420 предсказаниях: ни один контекст v1.0 не подменён ответом v0.4.

Парное сравнение joint минус v0.4 при 2048:

| Метрика | Разница | 95% ДИ | Победы / ничьи / поражения |
| --- | ---: | --- | --- |
| File | −0.250 | [−0.525, 0.025] | 3 / 9 / 8 |
| Function | −0.032 | [−0.194, 0.155] | 1 / 14 / 3 |
| Complete | −0.032 | [−0.087, 0.000] | 0 / 16 / 2 |
| Changed line | −0.071 | [−0.214, 0.000] | 0 / 13 / 1 |

Интервал File Recall касается нуля сверху, но точечная оценка ниже, поражений больше, чем побед, и остальные три метрики тоже ниже. Этого недостаточно, чтобы сменить базу. Повторный прогон v0.4 в `output/v10_baselines` совпал с первым по всем четырём метрикам на всех 20 задачах.

## Что именно сломалось

Пул кандидатов шире упакованного контекста. На joint при 2048 средний File Pool Recall равен 0.850, а упакованный File Recall 0.475. Function Pool Recall 0.619, упакованный 0.190. В среднем 0.40 золотых файла уже лежат в пуле и не попадают в контекст, и 0.15 золотых файла в пул не входят. Узкое место совместного отбора — не отсутствие файлов в объединении каналов, а остановка, как только именованные символы покрыты.

Правило остановки заранее такое: повторное покрытие того же свидетельства даёт нулевой прирост (`repeat_weight: 0`), и кандидат с непокрытым свидетельством не добавляется. На `django__django-12276` текст называет `FileInput`, `ClearableFileInput` и `use_required_attribute`. Joint кладёт два чанка одного файла и 127 токенов из 2048. v0.4 на той же задаче занимает 12 файлов и 2005 токенов. Незаполненный бюджет здесь не признак точности: пропущенные файлы просто не несут нового имени из текста задачи.

Первый однозадачный пробный прогон (`output/v10_smoke`) был ещё уже: один метод покрывал все три символа, потому что общие части CamelCase (`file`, `input`) считались определением `FileInput`. До диагностических 20 задач совпадение заменено на целый компонент имени, а путь из URL считается совпавшим, если путь репозитория является его суффиксом. Веса в yaml не менялись. Повторная проба `output/v10_smoke_exact` уже выбирает два символа, но по-прежнему один файл. Диагностический прогон шёл после этой поправки.

Группы зависимостей не чинят покрытие файлов. Paths при 2048 поднимает Changed Line до 0.1667, разница с v0.4 +0.019, интервал [−0.190, 0.214], 2 / 10 / 2. File при этом 0.375, разница −0.350, интервал [−0.600, −0.100] нуля не включает. Две задачи со строками — `astropy__astropy-8707` (0 → 0.333) и `sympy__sympy-24213` (0 → 1) — сидят рядом с потерями `pylint-dev__pylint-7277` (1 → 0) и `sympy__sympy-13878` (0.071 → 0). Это не устойчивый выигрыш.

Nested mode при 2048 сравнивает Function и Complete с v0.4 и даёт Changed Line 0.182 против 0.148, разница +0.034, интервал [−0.180, 0.238], 3 / 10 / 1. File падает до 0.500. Ограничение вложенности не является причиной проигрыша: независимый joint ещё ниже по строкам. Снимать вложенность ради замены v0.4 не из чего.

Coverage без графа и joint без structural совпали и оба хуже v0.4 по File (−0.300, интервал [−0.550, −0.050]) и Function (−0.147, интервал [−0.313, −0.008]).

## Остальные базы на тех же 20 задачах

`output/v10_baselines`, тот же счётчик и те же снимки. v0.9 — редкое имя, `configs/pathpack_v09_name.yaml`, без изменения этого файла.

| Метод | File | Function | Complete | Changed line |
| --- | ---: | ---: | ---: | ---: |
| bm25 | 0.350 | 0.1111 | 0.1111 | 0.1429 |
| graph-expand | 0.325 | 0.1111 | 0.1111 | 0.1429 |
| pathpack-v4 | 0.725 | 0.2024 | 0.0913 | 0.1480 |
| pathpack-v9, редкое имя | 0.950 | 0.2024 | 0.1468 | 0.0952 |
| pathpack-v10 | 0.475 | 0.1706 | 0.0595 | 0.0765 |

Joint выше BM25 по File на +0.125, интервал [−0.075, 0.325] включает 0. По Changed Line joint ниже BM25 на −0.066, интервал тоже включает 0. Против v0.9 по File разница −0.475, интервал [−0.700, −0.275], 0 / 10 / 10. v0.9 по-прежнему покупает файлы ценой строк и сам v0.4 не заменяет. Эти сравнения парные по тем же `instance_id`, но идут из двух каталогов прогона.

Embedding-only и lexical+embedding fusion не запускались. `sentence-transformers` не установлен, канал записан как `not_run`, модель `sentence-transformers/all-MiniLM-L6-v2`, ревизия `c9745ed1d9f207416be6d2e6f8de32d1f16199bf`. Веса не скачивались, случайные векторы не подставлялись. Поэтому ablation «без semantic» совпадает с joint: отключать было нечего. Текстовая модель не считалась заменой кодовой модели.

Синтетический тест в `tests/test_pathpack_v10.py` проверяет только механизм: два названных символа попадают в контекст, когда одиночный top-1 чанк v0.4 берёт один, а единственный разрешённый вызываемый добавляется группой путей и не добавляется чистым покрытием. Это не результат SWE-bench.

## Воспроизведение

```bash
.venv/bin/python -m unittest tests.test_pathpack_v10 tests.test_pathpack_v4 -q
.venv/bin/python -m codegraph_rag benchmark \
  --issues output/benchmark/issues.jsonl \
  --snapshots data/swebench/snapshots \
  --out output/v10_diag \
  --split dev --method pathpack-v4 pathpack-v10 \
  --budgets 1024 2048 4096 \
  --config configs/pathpack_v4.json \
  --v10-config configs/pathpack_v10.yaml --v10-ablations
HF_HUB_OFFLINE=1 HF_DATASETS_CACHE=output/benchmark/hf_cache \
  .venv/bin/python -m codegraph_rag score-run --run output/v10_diag
.venv/bin/python -m codegraph_rag benchmark \
  --issues output/benchmark/issues.jsonl \
  --snapshots data/swebench/snapshots \
  --out output/v10_baselines \
  --split dev --method bm25 graph-expand pathpack-v4 pathpack-v9 \
  --budgets 1024 2048 4096 \
  --config configs/pathpack_v4.json \
  --v9-config configs/pathpack_v09_name.yaml
HF_HUB_OFFLINE=1 HF_DATASETS_CACHE=output/benchmark/hf_cache \
  .venv/bin/python -m codegraph_rag score-run --run output/v10_baselines
```

Каталоги `output/v10_diag` и `output/v10_baselines` уже содержат эти прогоны. Повтор в тот же каталог намеренно отвергается. Новые зависимости не добавлялись: `configs/pathpack_v10.lock`.
