**Дата:** 1 ноября 2026 года  
**Статус:** первый работающий прототип retrieval, не подтвержденная научная новизна.

## Что сделано

1. Статический анализ Python через `ast`: определения, импорты, некоторые вызовы и наследование.
2. Нарезка на неперекрывающиеся фрагменты функций/методов (грубый первичный вариант).
3. Сравниваемые методы: `bm25`, `graph-expand`, `pathpack`.
4. PathPack выбирает BM25-семена, ищет пути длиной до 3 переходов по графу и использует веса связей. Фрагменты отбираются жадно при одинаковом приближенном бюджете токенов.
5. Два раздельных действия для реальных данных: `retrieve-batch` получает только текст запроса и репозиторий, `score` отдельно читает эталонные файлы из патча.
6. Для реальных Git-снимков перед поиском проверяется совпадение `HEAD` с `base_commit`; небезопасное отключение проверки возможно только явным флагом для учебных примеров.

## Как алгоритм устроен

* **BM25:** ранжирует фрагменты по тексту issue, имени файла и имени функции.
* **Graph expansion:** выбирает релевантные исходные функции и добавляет их соседей по графу.
* **PathPack:** учитывает нормированную BM25-релевантность, графовую близость и приблизительную стоимость фрагмента в токенах. Графовые пути могут проходить через узлы модулей и классов, которые не обязательно попадут в итоговый контекст. Лексическое начальное семя сохраняется, если укладывается в бюджет.

Сейчас это **эвристика**, а не доказанный новый алгоритм. Графовое преимущество может исчезать на реальных задачах; PathPack еще не улучшен относительно простого graph expansion.

## Измерение на учебном примере

В `examples/issue_demo/snapshot` создано 9 маленьких файлов, 4 вручную написанных описания ошибок и 4 целевых файла. Это **синтетическая демонстрация, не SWE-bench**. Метрика: в скольких случаях выбран хотя бы один фрагмент из целевого файла (0–4). Условия: 1 семя BM25, глубина графа 2, совпадающий бюджет оцененных токенов.

| Бюджет (оценка) | BM25 | Graph expansion | PathPack |
| --- | ---: | ---: | ---: |
| 45 | 0/4 | 0/4 | 0/4 |
| 70 | 0/4 | 1/4 | 0/4 |
| 110 | 0/4 | 4/4 | 4/4 |
| 160 | 1/4 | 4/4 | 4/4 |

**Вывод:** на искусственных кейсах графовый поиск помогает, но **PathPack не превосходит простое графовое расширение** на практически полезном бюджете 110. Это повод исследовать новое правило отбора, а не объявлять победу.

## Ограничения, которые обязательно писать в статье

- Оценка токенов: приблизительно `ceil(UTF8_bytes/4)`, это **не реальный токенизатор Gemma**.
- Граф статический и неполный: динамические вызовы, полиморфизм и сторонние зависимости часто не обнаруживаются.
- Пропускаются части module-level кода и сигнатуры классов; тестовые файлы исключены по умолчанию: нарезку нужно улучшать.
- Зависимости иногда проходятся в обратную сторону: это эвристика обнаружения, а не корректная модель исполнения.
- Нет embedding baseline, реальных SWE-bench результатов, запуска Gemma или проверки исправлений тестами.
- Четыре учебные задачи не позволяют судить о научной значимости, обобщаемости или шансах на приз.

## Команды

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[viz]'
python -m unittest discover -s tests -v
python examples/issue_demo/run_demo.py
codegraph retrieve examples/issue_demo/snapshot --query 'login cookie causes failure' --method pathpack --budget 110 --seeds 1 --hops 2
```

Реальные задачи:

```bash
pip install -e '.[benchmark,viz]'
codegraph prepare --limit 80 --dev-count 20 --seed 42 --out output/benchmark
# Ручная подготовка snapshots/<instance_id> на base_commit; repo HEAD проверяется автоматически
codegraph retrieve-batch --issues output/benchmark/issues.jsonl --snapshots snapshots --split dev --method pathpack --budget 2048 --out output/dev_pathpack.jsonl
codegraph score --predictions output/dev_pathpack.jsonl --gold output/benchmark/gold_labels.jsonl --out output/dev_scores.json
```

Важно: не предоставлять файл `gold_labels.jsonl` алгоритму поиска или модели. Эталонные исправления допустимы только в отдельном процессе оценки.
