# PathPack: локализация правок под токен-бюджетом

[English](README.md) | **Русский**

PathPack: исследовательский код для выбора фрагментов репозитория, которые малый локальный агент может прочитать в фиксированном токен-бюджете. Главный вопрос: где будет правка, а не какие файлы похожи на текст задачи.

Проект содержит:

- граф кода на Python и конвейер поиска (PathPack v0.4 и его продолжения);
- PathPack-H: модель вероятности правки, обученная на истории репозиториев (воспроизведение истории, без меток бенчмарка);
- PathPack-U: упаковку контекста, которая максимизирует взвешенную сумму ожидаемых File, Function, Complete Function и Changed Line Recall;
- код оценки с замороженными сплитами, парным bootstrap, файлами заморозки и сводками прогонов;
- пробу локализации локальной моделью Gemma 4 E2B.

## Основные результаты

Все числа даны при бюджете 2048 условных токенов (`ceil(UTF-8 bytes / 4)` по сериализованному контексту). Это не подсчёт токенизатором Gemma.

На 100 отложенных задачах SWE-bench Verified, PathPack-H против PathPack v0.4:

| Метрика | v0.4 | PathPack-H |
|---|---:|---:|
| File Recall | 0.847 | 0.803 |
| Function Recall | 0.192 | 0.529 |
| Complete Function Recall | 0.094 | 0.303 |
| Changed Line Recall | 0.169 | 0.445 |

На двух дополнительных отложенных наборах (51 и 125 задач) PathPack-U превосходит v0.4 по всем четырём метрикам. Модели, обученные без истории целевого репозитория, дают те же результаты. Проба с Gemma 4 E2B измеряет только локализацию: патчи не генерируются и тесты не запускаются.

## Структура

- `src/codegraph_rag/`: разбор кода, чанкинг, поиск, версии PathPack и конвейер PathPack-R/E/H/U (`src/codegraph_rag/pathpack_r/`).
- `scripts/`: драйверы экспериментов, построение сплитов, генерация рисунков и ноутбука, проба с Gemma.
- `tests/`: модульные тесты разбора графа, поиска, защит от утечки, учёта бюджета и правил обучения.
- `configs/`: замороженные конфигурации.
- `output/`: сводки прогонов (CSV и JSON), на которых основаны статьи, а также ответы пробы с Gemma и файлы заморозки. Предсказания по задачам, модели и кэши в репозиторий не входят.
- `docs/`: статьи, тексты для конкурса, рисунки и отчёты.

## Установка

Рекомендуется Python 3.12.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[notebook]"
```

Данные бенчмарка в репозиторий не входят. SWE-bench Verified читается из набора Hugging Face `SWE-bench/SWE-bench_Verified`. Снимки репозиториев на точных `base_commit` создаёт `scripts/fetch_snapshots.py` из локальных клонов. Каталог снимков задаётся в скриптах (по умолчанию `data/swebench/snapshots`).

## Воспроизведение основных результатов

Модульные тесты (для большинства из них данные бенчмарка не нужны):

```bash
PYTHONPATH=src python -m unittest tests.test_pathpack_e tests.test_pathpack_r tests.test_pathpack_v10e
```

Сводки замороженных отложенных прогонов уже лежат в `output/`. Ноутбук строит таблицы и рисунки по ним:

```bash
python scripts/write_pathpack_h_notebook.py
jupyter nbconvert --to notebook --execute --inplace notebooks/11_pathpack_h.ipynb
```

Повторный запуск отложенных экспериментов требует снимков репозиториев и кэша воспроизведения истории. Команды и файлы заморозки, записанные до каждого прогона, перечислены в разделе воспроизводимости статьи [docs/PAPER_RU.md](docs/PAPER_RU.md).

Файлы заморозки (хэши дерева исходников и моделей, гипотезы, записанные до прогона): [output/pathpack_e](output/pathpack_e) и манифесты в [output/pathpack_r_splits_v2](output/pathpack_r_splits_v2).

## Ограничения

- Патчи не генерируются, тесты не запускаются. Статья измеряет локализацию и покрытие контекста, а не долю исправленных ошибок.
- Отложенные наборы малы (от 51 до 125 задач), в самом большом преобладает django.
- История воспроизводится по снимку на самом раннем базовом коммите, а не по дереву на момент каждого исторического коммита.
- Оценивались только Python-репозитории из SWE-bench.
